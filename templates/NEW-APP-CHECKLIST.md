# New TMApps app or branch checklist

- [ ] Create/link the actual app branch; select the app name, stable KB prefix,
  approved colour and white icon. Do not publish template placeholders.
- [ ] Copy the latest main APP-STANDARDS.md, standards/requirements.json,
  AGENTS.md and .cursor/rules/app-standards.mdc, security-data.mdc and
  kb-maintenance.mdc. Preserve app-specific security and release instructions.
- [ ] Create APP-COMPLIANCE.md with evidence and open gaps for every requirement.
- [ ] Default to Bubble and use Finance Settings. Complete and push one verified
  theme update at a time in Bubble, Finance, ArtCraft-inspired, Blocky Basic order.
- [ ] Implement all remaining shared features, offline behaviour, setup/help,
  accessibility, crash-report review and bounded resource use.
- [ ] Prepare startup animation proposals and obtain owner selection before code.
- [ ] Build/test actual native OS versions/architectures and record limitations.
- [ ] Register verified packages/hashes/branding/notes with Launcher; keep Agent
  Office last and SocialsManager immediately before it.
- [ ] Publish the branded named Word KB after complete render/visual QA, link the
  Master KB on page one and update registry/Wiki with stable article IDs.
- [ ] Review README/SECURITY, affected guides/tours/notes and sensitive-data scan.
  Record functional/performance/native checks and any unrun checks before release.
- [ ] Add accurate app/OS records to the shared GitHub Project and app labels;
  use version tags only with verified source/build provenance.
- [ ] Create an accurate showcase video using sanitized real app features.

Licensing, usage-rights/legality and legal policies remain deferred by the owner.
Do not choose a licence or alter existing notices as part of this checklist.
