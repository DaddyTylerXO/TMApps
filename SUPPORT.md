# Help and reports

Start with the affected app's branch README and its in-app Help/KB. [The project table](README.md#projects) links every application branch. Include the app name and installed version whenever requesting help.

| Request | Destination |
| --- | --- |
| Bug or crash | [Bug report](https://github.com/DaddyTylerXO/TMApps/issues/new?template=bug-report---%2Aapp-name%2A---%2Abug%2A.md) |
| Feature idea | [Feature request](https://github.com/DaddyTylerXO/TMApps/issues/new?template=feature-request---%2Aapp-name%2A---%2Afeature%2A.md) |
| Installation, download or other issue | [General issue](https://github.com/DaddyTylerXO/TMApps/issues/new?template=general-issue.md) |
| Security vulnerability | [Private report](https://github.com/DaddyTylerXO/TMApps/security/advisories/new); read [SECURITY.md](SECURITY.md) |

Public issues and attachments are visible to everyone. Review crash drafts, logs and screenshots before submitting. Remove credentials, mail, private file contents and personal information. Use synthetic examples when possible.

For a download problem, include the asset filename, download URL, OS/processor, error and whether its checksum matched. Never attach a real vault, account store or authentication backup. See [DOWNLOADS.md](DOWNLOADS.md) for the current package index and checksum instructions.
